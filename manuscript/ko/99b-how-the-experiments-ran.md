# 부록 A. 실험을 어떻게 돌렸나

장마다 날짜, 도구, 모델을 숫자와 함께 적었다. 이 부록에는 나머지를 적는다. 세션을 어떻게 띄웠는지, 저장소마다 무엇이 들어 있었는지, 무엇을 셌는지, 판정 테스트가 어떻게 판정했는지다. 판정 테스트는 AI에게 보여 주지 않는 테스트이고, 나는 이것으로 실행 결과가 맞는지 가린다.

## 실행 묶음 셋

실험은 세 묶음으로 돌렸다.

- **2026-11-22, Claude Code 2.1.330.** 장마다 그 장의 예제를 담은 작은 저장소에서는 모델이 가장 높은 설정의 Claude Opus 5.5였다. 실험마다 버전별로 세션 10개를 계획했다. 그달의 API 크레딧이 떨어져서 6~9개에서 멈춘 것이 있고, 어느 것이 그런지는 장마다 적었다. 큰 저장소에서는 기본 설정의 Claude Haiku 5.5, Claude Sonnet 5.5, Claude Opus 5.5를 썼다.
- **2026-11-22, 23, 25, Codex CLI 0.171.0(OpenAI의 코딩 에이전트).** 모델은 기본 설정의 gpt-6.2-sol이었다. 11월 25일에 돌린 것은 이 책을 고쳐 쓰면서 더한 재실험이다.
- **2026-11-25, Claude Code 2.1.331.** 16장 종합 실험에는 기본 설정의 Claude Sonnet 5.5와 Claude Haiku 5.5를, 이 책을 고쳐 쓰면서 더한 실험에는 기본 설정의 Claude 모델 셋을 썼다.

## 세션을 띄운 방법

- **Claude Code**는 사람이 끼지 않고 세션 하나를 돌리는 `claude -p`로 돌렸다. 사용자 설정, 훅, 연결된 서버, 자동 메모리는 껐다. 세션은 파일을 읽고 고칠 수 있었고, `python3`, `python`, `ls`, `cat`, `git`, `grep`, `find`, `head`, `wc`를 실행할 수 있었다. 여러 명령을 이은 명령 줄 안에서는 `sed`와 `echo`가 돌기도 했다.
- **Codex CLI**는 `codex exec`로 돌렸다. 내 사용자 설정과 Codex의 명령 규칙을 껐고, 웹 검색, 브라우저, 컴퓨터 조작, 이미지 생성, 앱, 여러 에이전트, 목표, 도구 추천도 껐다. 샌드박스는 세션이 저장소 안에는 쓰고 `.git`에는 쓰지 못하게 했다. 그래서 Codex 세션은 하나도 커밋하지 못했다.
- **모든 실행은 처음 저장소를 새로 복사한 곳에서 시작했다.** 복사본에는 커밋이 하나 있다. 15장처럼 검수할 마지막 커밋이 필요한 실험에서는 세션이 시작하기 전에 스크립트가 그 커밋을 만들었다. Codex 세션은 한 번에 하나씩, Claude Code 세션은 한 번에 여덟 개까지 돌렸다. 2026-11-25에는 Codex 모델의 응답이 자주 늦어서, 3분 동안 아무것도 쓰지 않은 Codex 세션은 멈추고 새 복사본에서 그 회차를 다시 시작했다.
- **규칙 파일.** Codex는 `AGENTS.md`를 읽고, Claude Code 2.1.331도 `AGENTS.md`를 읽었다. 저장소가 내 컴퓨터에서 Claude Code가 쓰는 임시 폴더 안에 있을 때는 Claude Code 2.1.331이 `AGENTS.md`도 `CLAUDE.md`도 읽지 않았다. 그래서 종합 실험은 내 홈 폴더 아래의 폴더에서 돌렸다. 실행 폴더 위쪽의 어느 폴더에도 지시 파일은 없었다. 11월 22일의 작은 저장소와 큰 저장소에는 규칙 파일이 없었다.

## 저장소

- **작은 저장소**에는 한 장의 예제가 들어 있다. 그 장이 밝힌 파일 한두 개를 더한 것도 있다.
- **큰 저장소**는 지어낸 가게로, 파일 518개(그 가운데 파이썬 파일 516개)와 테스트 1,317개가 있다. 장마다 함정을 담은 코드는 내가 썼다. 나머지 모듈 210개는 Claude Haiku 5.5가 만들었고, import되고 제 테스트를 통과하는 모듈만 남겼다.
- **16장의 두 저장소.** 저장소 A는 파이썬 파일 47개, B는 55개이고, 둘 다 3,400줄쯤이며 보이는 테스트 259개가 같다. 내가 쓴 설계를 보고 Codex가 두 저장소와 요청마다의 기준 풀이를 만들었다. 나는 두 저장소가 같은 호출 926번에 같은 답을 내는지, 기준 풀이가 모두 판정 테스트를 통과하는지, 일부러 심은 틀린 풀이 16개가 판정 테스트에 걸리는지 확인했다.

## 센 것

- **도구 호출.** Claude Code에서는 도구를 한 번 쓴 것이 한 번이다. 파일 읽기, 고치기, 검색, 셸 명령이 그렇다. Codex에서는 셸 명령 하나와 파일 고치기 한 번이 한 번씩이다. Codex 0.171.0은 도구 호출 하나 안에서 명령을 여러 개 실행할 수 있고, 그 명령을 하나하나 센다.
- **연 파일.** 세션이 읽은 처음 저장소의 파일. 읽기 도구로 읽었거나, 파일 내용을 찍는 셸 명령(`cat`, `head`, `tail`, `nl`, `sed -n`)으로 읽은 것을 센다. `payments/*.py` 같은 와일드카드는 그 폴더에서 맞는 파일을 모두 세고, 명령 안의 `cd`는 따라간다. `grep`, `rg`, 검색 도구로 찾은 것은 연 파일로 세지 않는다. 11월 22일의 Claude Code 실행은 그보다 먼저 쓴 단순한 규칙으로 셌다. 읽기 명령 몇 가지에 적힌 `.py` 파일을 세고, `cd`는 따라가지 않았다. 두 규칙 모두 세션이 실행한 명령에서 무엇을 읽었는지 어림한다.
- **턴.** 한 세션에서 모델이 답한 횟수를 Claude Code가 센 값.
- **토큰.** 한 세션에서 모델이 읽고 쓴 것 전부. 캐시에서 읽은 토큰도 넣는다.
- **비용.** 세션마다 Claude Code가 낸 추정값. 11월 22일분은 Anthropic 콘솔의 청구액이 추정값의 합보다 4%쯤 많았다.

## 판정 테스트가 판정한 방법

- 판정 테스트는 세션 밖에서, 세션이 남긴 저장소에 대고 돈다.
- 16장에서는 요청마다 판정 테스트가 둘이다. 첫째는 요청이 바라는 새 동작을 본다. 변경 전에는 실패하고 변경 뒤에는 통과해야 한다. 둘째는 미리 기록해 둔 가게의 바깥 함수 호출 926번을 돌리고, 그 답을 바꾸기 전 저장소의 답과 견준다. 요청이 바꿔도 되는 호출은 빼고 견주며, 그 호출은 요청마다 실행 전에 정해 두었다. R07은 질문만 하고 코드를 바꾸지 않는 요청이어서, 나머지 테스트는 바뀐 파일이 없는지를 본다. 고친 R02의 나머지 테스트는 하위 도메인 주소로 가입하는 호출 하나를 빼고 925번을 돌린다. R01의 나머지 테스트는 새 내보내기가 캐시를 그대로 두는지도 따로 본다. 요청이 그렇게 하라고 했기 때문이다.
- **판정 테스트는 요청이 말한 것, 또는 같은 경우에 저장소의 코드가 이미 하는 것만 요구할 수 있다.** 16장의 요청 스무 개를 이 기준에 2026-11-23에 대 보았고, Claude 실행에서 내가 놓친 경우들이 드러나 2026-11-25에 다시 대 보았다. 기준을 어긴 것이 세 가지였고, 세기 전에 고쳤다. 이 기준은 새 동작 테스트가 무엇을 요구해도 되는지를 가린다. R04의 나머지 테스트는 그대로 둔다. R04는 일부러 둥근 값을 요구하고, 그 나머지 테스트는 37이나 48을 바꾼 변경을 실패로 친다. 결제사의 한도가 그 값을 요구하고, 그것을 말해 주는 것은 저장소 B의 주석뿐이기 때문이다. 그래서 R04는 코드가 이유를 담고 있는지를 시험하는 요청이 되고, 7장도 그렇게 적는다.
  - R02의 새 동작 테스트는 오류 코드 `email_blocked`를 요구했고, 두 테스트 모두 하위 도메인 주소를 받아들이라고 요구했다. 요청은 오류 코드를 정하지 않았고, 하위 도메인도 정하지 않았다.
  - R13의 판정은 문턱값 `-1`, `1.5`, `True`에 `ValueError`를 요구했다. 가게의 코드는 잘못된 재고 입력에 `StockError`를 낸다.
  - 새 동작 테스트 아홉 개는 예외 클래스의 이름을 정해진 이름과 그대로 견줬다. R14의 요청은 "must raise ValueError"라고 하는데, `ValueError`를 물려받은 클래스도 `ValueError`다. 그래서 이 테스트들이 정해진 이름을 예외가 물려받은 모든 클래스의 이름과 견주게 고쳤다. 나머지 테스트는 여전히 그대로 견준다.
  - 요구 세 가지는 가게의 코드가 이미 정해 두어서 기준을 통과했다. 없는 고객에 대한 `KeyError`(R01), 내림하는 카드 수수료(R05), 잘못된 쿠폰 비율에 대한 `CouponError`(R10)다.
  - 고친 판정으로 세션을 판정하기 전에, 바꾸기 전 두 저장소와 기준 풀이에 먼저 돌렸다. 예외 이름을 고친 비교는 바꾸기 전 저장소, 기준 풀이, 일부러 심은 틀린 풀이 모두에서 옛 비교와 같은 판정을 냈다. 원래 판정 결과도 지우지 않고 남겨 두었다.
- **결과 다섯 갈래.** 16장의 실행은 모두 다섯 갈래 가운데 하나로 나눈다. 11월 25일 Sonnet의 처음 312번을 본 뒤, 나머지 실행을 돌리기 전에 적었고, 모든 실행에 썼다. 통과, 요청한 동작 실패, 요청하지 않은 동작이 바뀜, 출력에 키 하나가 더해지고 나머지는 그대로, 파일을 하나도 바꾸지 않고 진행하기 전에 물음. 출력에 키가 더해진 실행은 실패로 세고, 그 장에는 그런 실행을 빼고 센 합도 함께 적는다.
- 세션이 테스트를 돌리면 저장소에 `.pytest_cache` 폴더가 남을 수 있다. 판정 테스트가 원래 `__pycache__`를 빼고 보듯이, 이 폴더는 판정 전에 지웠다.

## 한국어판의 금액

한국어판의 예제 코드는 원을 쓴다. 실험은 영어판의 코드와 프롬프트로 돌렸으므로, 실험 결과에 나오는 금액은 영어판과 한국어판 모두 센트다.

## 한계

- 모든 저장소의 두 버전은 내가 설계했고, 요청은 모두 내가 썼다. 그래서 실험마다 시험한 것은 내가 만든 습관의 한 모양이다.
- 버전마다 10번 돌리면 큰 차이는 보이지만 작은 차이는 놓친다(16장에 셈이 있다).
- 숫자는 모두 함께 적은 도구 버전과 모델의 것이다. 전체 표와 나중 모델의 실행은 저장소의 `experiments/RESULTS.md`에 있다.
